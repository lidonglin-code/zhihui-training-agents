# 知汇 · 企业培训 AI 智能体

一套面向企业培训负责人与讲师的本地 AI 工作台。用户提供真实材料和少量必要信息，系统将其与各智能体内置的专业方法结合，调用用户自己的大模型 API，生成可编辑、可继续修改、可复制和可导出的工作成果。

项目坚持“先解决真实问题”：界面尽量简单，专业分析、证据规则、成果结构和质量检查主要由后台提示词承担。

## 八位智能体

1. 项目架构顾问：判断培训是否是合适解法，形成可执行的培训项目方案。
2. 经验萃取专家：从真实事件中还原线索、判断、动作与适用边界。
3. 微课开发专家：围绕一个真实小任务生成可制作、可练习的微课方案。
4. 案例开发专家：把真实事件改编为有决策张力的教学案例和教学指引。
5. 活动设计专家：生成能够在课堂上直接运行的活动流程与讲师脚本。
6. 智能题库助手：依据课程材料生成带答案、解析、来源和质量检查的题目。
7. 运营文案助手：生成首发、提醒、临期等不同阶段的培训运营文案。
8. 培训评估顾问：围绕真实管理决策生成够用、可执行的评估方案和工具。

## 运行环境

- Node.js 20 或更高版本
- npm
- 任一受支持模型服务商的 API Key

## 下载与启动

```bash
git clone https://github.com/lidonglin-code/zhihui-training-agents.git
cd zhihui-training-agents
npm install
npm start
```

然后打开：<http://127.0.0.1:4173/>

必须使用 `npm start` 或 `node server.mjs` 启动。普通静态文件服务只能显示页面，无法解析文件或调用大模型。

## 模型接入

当前内置以下服务商的经济、均衡和高质量档位：

- DeepSeek
- 硅基流动
- 智谱 AI
- 阿里云百炼
- Kimi
- OpenAI

模型档位会映射到具体模型，用户也可以在高级设置中填写兼容 OpenAI Chat Completions 的接口地址与模型名称。

页面会显示密钥与材料实际发送的域名。自定义服务须先确认信任；仅支持公网 HTTPS 接口（443 端口），不支持本机、局域网模型或接口重定向。

API Key 只保存在当前页面的内存中，刷新或关闭页面后失效；本地服务不会把密钥写入文件、日志、项目记录或导出成果。生成时，用户材料会发送给所选模型服务商，敏感材料请先匿名化。

## 文件与数据

- 支持 PDF、DOCX、TXT、Markdown、CSV 和 JSON。
- 每个文件最大 8MB，每次任务最多 8 个文件。
- 文件由本地 Node 服务提取文字，不会保存到项目目录。
- 扫描版 PDF 需要先进行 OCR，当前版本不识别图片中的文字。
- 输入与生成结果保存在当前浏览器的本地存储中，API Key 不会保存。
- 开始生成后会暂存已读取的材料文字和已完成片段，以便暂停、刷新或连接恢复后继续；完成后保留材料依据供继续修改，均可通过“清除数据”删除。浏览器空间不足时会明确提示，此时应保持页面打开。
- 点击顶部“清除数据”，确认后可删除本应用的输入、成果及旧版草稿，清空内存中的上传材料与模型连接。其他打开的工作台标签页也会刷新；显示主题保留。已下载文件和模型服务商保存的记录需要另行管理。
- 页面使用系统字体，不请求 Google Fonts；模型请求由本机服务转发，浏览器不直接连接模型服务商。

## 成果生成机制

每个智能体拥有独立的输入字段、方法论、后台分析流程、成果章节和质量红线。用户只需点击一次，后台会根据任务自动选择一次生成或“整体设计—按章生成—事实与一致性审稿”。微课、项目、案例、活动和评估默认按章节处理；超过 6 道的题库按每批最多 5 道处理，并检查编号、答案、解析、来源和重复题目。材料不足时允许减题，但必须说明实际数量与原因。

长材料按段提取任务依据并保留尾段，后续章节共享整体目标、约束和已完成内容。单次输入超过约 25.6 万字符时会明确要求按主题拆分，不会悄悄丢弃材料尾部。

请求会按阶段调整输出预算和思考强度，模型名称与厂商不会自动更换。DeepSeek 使用 JSON Object 模式；硅基流动使用现有 Schema 模式；已适配的千问系列使用 JSON Object 模式。其他接口继续使用提示词格式约束及结果校验，不假定所有模型支持相同能力。预算与阶段策略集中在 `dist/model-policy.js`，厂商能力变更仍需人工维护。

系统区分格式错误、正文截断、空正文、服务繁忙和鉴权失败：可安全修复的标点与转义错误先在本机处理，其他问题只重试当前部分；截断内容不能通过补括号冒充完整成果。审稿只返回必要章节的修订和质量检查，不再每次重写整份正文。所有最终成果仍须通过原有专属完整性检查，半成品不标记为已完成。

遇到故障可点击“继续生成”，复用已通过检查的部分。输入、材料或修改要求变化时会开启新的生成任务。每轮最多 32 次请求、约 26 万的累计请求输出预算，并在 12 分钟后停止发起新请求；触及上限时保留进度，由用户决定是否继续。实际消耗取决于服务商返回的用量；分段、审稿与重试可能产生多次计费请求。

所有成果均可在线编辑、复制、继续让 AI 修改，并导出为 Markdown 文件。

```bash

```

测试覆盖 8 个智能体的方法与提示词契约、6 家模型服务商与 3 个质量档位的本地模拟路由、安全边界，以及真实长成果故障的模拟：空正文、截断、JSON 错误、暂停与刷新续作、审稿失败、长材料尾段、30 题分批、材料不足、服务重试及鉴权停止。模拟测试不使用真实 API Key，也不等同于厂商实时可用性和专业内容质量的实测。

## 主要目录

```text
dist/                 前端页面、样式、智能体数据与产品素材
scripts/              方法契约、模型路由与介绍页构建脚本
server.mjs            本地静态服务、文件解析与模型请求代理
server-security.mjs   公网地址校验、TLS 连接与本地请求防护
package.json          运行与测试命令
```

关键文件：

- `dist/workflow-data.js`：各智能体输入、示例和成果章节
- `dist/theory-data.js`：面向用户的方法说明
- `dist/engine-data.js`：后台专业流程、证据规则和质量门槛
- `dist/provider-data.js`：模型服务商与质量档位映射
- `dist/app.js`：交互、提示词组装、结果校验、编辑和导出
- `dist/generation-core.js`：分段生成、局部恢复、检查点与审稿协调
- `dist/model-policy.js`：阶段预算、应用上限和思考强度策略
